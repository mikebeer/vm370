## What V0.1 is

VM/370 Community Edition's CP, converted to run on an **ESA/390** machine
(Hercules 3.13, `ARCHMODE ESA/390`): channel subsystem I/O, 4 KB storage keys,
1 MB segments with fullword page-table entries, the dropped S/370 instructions
simulated for guests. It IPLs, initialises, takes operator commands, logs users
on, and runs CMS from the system disk.

The recipe:

```
ipl 6A1  /  cold  /  enable all  /  cp disc
logon maint cpcms noipl  /  def stor 16m  /  ipl 190
```

## What V0.1 is not, stated plainly

- **`IPL CMS` (the named saved system) fails** with `FRE013`: `DMKCFG`
  indexes the segment table with `DMKSNT`'s 64 KB segment numbers (`I-195`).
  Shared segments at 1 MB granularity are the design item in `04`/`05`; `NOIPL`
  + `IPL 190` is the bypass. Next on the list.
- **The profile EXEC dies** with `DMSITP141T PROTECTION EXCEPTION … DMSREX`
  (`I-202`); CMS recovers to `Ready;`. R-12 (two 2 KB keys per 4 KB frame) is
  the candidate.
- `DEF STOR 16M` is needed because MAINT's directory gives 15 MB and CMS's
  nucleus sits at 15.5 MB.
- **DMKDMP cannot write its dump** (`I-201`); abend registers come from
  Hercules.
- 24-bit virtual addressing only. 31-bit virtual (M4) and real storage above
  16 MB (M5) are not in this version.
- Tested on Hercules 3.13; 4.9.1 comparison pending.

## How it got here

`28-IPL-WALLS.md` has every wall with the trace that located it; `13-ISSUES.md`
I-194 to I-202 the night of 3–4 October. The one lesson repeated five times in
one night: **trace the fixed branch source, not the moving landing site**, and
read the bytes in the nucleus before believing a build carried a fix.
