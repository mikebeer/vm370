# M7.3 — ESA/390 guest DAT, and the ESA/390 deviations register (7 October 2026)

This document has three parts:
- how CP shadows an ESA/390 guest's own translation tables (DMKVAX);
- **every place where VM/370+ deviates from ESA/390** for an ESA/390 virtual machine, with its consequences;
- what the 64-bit milestone (M9) inherits from all of this.

## 1. Why a new path, and not DMKVAT's tables

`DMKVAT` shadows S/370-format guest tables and is parameterised by eight
CR0 page/segment geometries (`ARCHTECT`). Three facts ruled it out for
ESA/390 guests:

- `CHKFORM` rejects CR0 bit 10, so an ESA/390 CR0 (byte 1 = X'B0') takes a
  translation-specification exception. That was Linux's stop at `paging_init`
  in lx12.
- The `X'B0'` row is an older fullword format, not ESA/390:
  - the page-frame address is shifted by 8;
  - the segment-table entry keeps its length in byte 0 and its invalid bit at X'01';
  - the page-protection bit X'200' counts as "must be zero".
- **The shadow tables DMKVAT builds for the hardware are still S/370
  format**, and the hardware is ESA/390. Guest DAT was therefore broken on
  VM/370+ for *every* guest; no test had used it before.
  - S/370 geometries (64 KB segments, 2 KB pages) cannot be shadowed 1:1
    onto ESA/390 hardware tables.
  - **Limitation:** S/370 guests running their own DAT are unsupported on
    VM/370+ (see D-13).

## 2. DMKVAX

A new CSECT appended to the DMKVAT assembly (deck `DMKVAT.XA0054DK`). For an ESA/390 guest (`VMESA390`), each `DMKVAT` entry branches to it first:

| DMKVAT entry | DMKVAX | Called by | Does |
|---|---|---|---|
| `DMKVATAB`, `DMKVATMD` | `DMKVAXAB`/`MD` | DMKDSP, DMKPRV (LCTL, PTLB), DMKCFG | pending invalidations; recompute the shadow STDs |
| `DMKVATBC` | `DMKVAXBC` | DMKDSP (leaving EC/translate mode), logoff | release everything |
| `DMKVATSX`, `DMKVATPX` | `DMKVAXFL` | DMKPRG (real segment/page-translation exception) | walk the guest tables; reflect X'10'/X'11'/X'12'/X'05', or fill in the shadow |
| `DMKVATRN`, `DMKVATLA` | `DMKVAXRN`/`LA` | DMKPRV (operand translation, LRA) | walk; host real address or guest real address |
| (new) | `DMKVATES` | DMKDSP CHKTRAN, every dispatch in translate mode | R0/R1 = shadow CR0/CR1; loads real CR7, CR13 and CR3 |

**Geometry is identical**: 1 MB segments of 4 KB pages, fullword entries.
So a shadow table is the guest's table entry for entry, with real frames:

- **Shadow segment table:**
  - 2048 entries, 8 KB, on a 4 KB boundary (one 12 KB `DMKFREE` block);
  - invalid entries hold X'00000020';
  - shadow STD = shadow origin | the guest STL.
- **Shadow page table:**
  - always 256 entries (PTL 15), 64-byte aligned;
  - its `DMKFREE` address is kept at +1024;
  - all entries start invalid (X'00000400') and are filled on demand.
- **Shadow PTE** = real frame | the guest PTE's protect bit (X'200').
- **Address spaces:**
  - Up to **four guest STDs** are shadowed at once (the DATBLK, which `EXTSHSEG` points at). When all four are in use, the next new STD takes one over in turn.
  - Real CR1, CR7 and CR13 each get the shadow of the guest's CR1, CR7 and CR13. Linux 31-bit runs its kernel in **home space**, and copies user data with `MVCP`/`MVCS` through the **secondary space**.
  - A real fault names its space in the translation-exception identification bits 30-31, so the walk uses the matching guest CR.
- **Invalidation** reuses CP's existing flags. `VMINVPAG` is set by DMKPTR when it steals a frame, by `PTLB`, and by `IPTE`; `VMINVSEG` and `VMNEWCR0` come from `LCTL`. On the next dispatch, every shadow page table is freed, every shadow segment entry is set invalid, and `CPPTLBR` purges the TLB.
- **Real CR0** = CP's CR0 plus the guest's secondary-space control (bit 5).
- **Real CR3:** the guest's CR3, with an all-keys PSW-key mask while the guest is in virtual supervisor state. `MVCP` and `MVCS` then run natively in the real problem state, as they would in the supervisor state the guest believes it is in.

Simulated beside it (DMKVCS, routed from DMKPRV for ESA/390 guests only):
- `IPTE`: sets the guest PTE invalid, then `VMINVPAG`.
- `SAC`/`SACF`: set PSW bits 16-17. Home mode is privileged in the real problem state the guest runs in.

DMKDSP's PSW check no longer treats bits 16-17 (address-space control) as must-be-zero for an ESA/390 PSW.

**Test:** `tests/guest390/g390e`, run g390e8 and later:

| Test | Result |
|---|---|
| `SPX` (prefix page = copy of page 0 plus a marker) | "PREFIXED" at real X'200' |
| DAT on, primary space, virtual X'8000' → real X'9000' | "REAL9000" |
| DAT on, home space (CR13, PSW ASC 11) | "REAL9000" |
| `IPTE` virtual X'8000`, then a load | X'11', translation-exception identification X'8000' |
| invalid segment (X'200000') | X'10', translation-exception identification X'200000' |

**Linux 4.0 31-bit** (lx22 onwards) now runs with DAT on, through
`paging_init`, memory setup, `cmma_init`, `time_init` and the CHSC probes.

### Bugs found on the way (all in new M7 code)

| Run | Symptom | Cause |
|---|---|---|
| g390e4/5 | CP **PRG005**, `DMKDMP908I` | VXWALK uses R4, which still held the shadow-set pointer. Found with Hercules `pgmtrace +05` |
| lx16/17 | lowcore empty after `SPX` | `LA R5,0(R7,R8)`: CP runs **AMODE 24** and Linux's prefix is X'3FFE000', so `LA` dropped the top bits |
| lx19 | — | `TRANS` without `OPT=AMODE31` cuts a guest-table address above 16 MB to 24 bits (TRL31) |
| lx21 | every fault reflected as X'11' | `LA R0,1(,R0)`: **base register 0 means "no register"**, so R0 became 1 and every page table looked 16 entries long. Found with the diagnostic ring `DMKVATRG` (16 entries of fault address, STD, code and frame; display it with `DCP`) |
| g390e6 | home-space `LPSW` gave a specification exception | the EC-mode must-be-zero mask covered PSW bits 16-17 |

## 3. Deviations register: VM/370+ ESA/390 virtual machine vs ESA/390

| ID | Deviation | Consequence | Where |
|---|---|---|---|
| D-1 | **No virtual prefixing.** `SPX P` copies page P to page 0, which stays the lowcore. `STPX` answers 0 | Only uniprocessor guests are correct. Writes through absolute P after the `SPX` are not seen at real 0. Rules out SMP guests | DMKVCS VCSSPX/VCSSTPX |
| D-2 | **Format-1 CCWs converted in place** to format 0 for the duration of the I/O | The guest sees its channel program altered while the I/O runs | DMKVCS CVTCHN/UNCVT |
| D-3 | **No IDAWs; CCW data addresses must stay below 16 MB** | I/O buffers above 16 MB fail: must be fixed before real Linux I/O | DMKVCS, DMKCCW |
| D-4 | **Channel status simplified:** one subchannel per device; CE merged with an already queued DE; ESW zero; the ISC mask is ignored (any CR6 bit enables all); no `CHSC`, `RSCH`, `SCHM` | No multipath, measurement or fine-grained ISC masking | DMKVCS, DMKDSP |
| D-5 | **`SERVC` and `STSI` → cc 3** | No SCLP console or SCLP memory information; Linux falls back to `TPROT` and the 3215 | DMKVCS |
| D-6 | **`STFL` = N3 only** | z900-level ESA/390 guests only | DMKVCS |
| D-7 | **`TPROT`:** cc 0 below the virtual machine's size, cc 3 above; no key, page-protection or DAT test | Fine for memory sizing; wrong for protection tests | DMKVCS VCSTPROT |
| D-8 | **Four shadowed STDs at most**; no AR mode, subspaces or ASN translation | Programs using AR mode are unsupported | DMKVAX |
| D-9 | **`IPTE` invalidates every shadow table** | Correct but slow under heavy `IPTE` use | DMKVCS VCSIPTE |
| D-10 | **`SAC`/`SACF` without their special-operation checks** | A buggy guest misses a program check | DMKVCS VCSSAC |
| D-11 | **Real CR3 has an all-keys PSW-key mask** in virtual supervisor state | Matches supervisor-state semantics | DMKVAX DMKVATES |
| D-12 | **`CHANGE RDR … KEEP`** is not known to VM/370 CP (Linux's `DIAG 8` after IPL) | Cosmetic message | DMKCSP (unchanged) |
| D-13 | **S/370 guests with their own DAT are unsupported** on VM/370+ | Their shadows would be S/370 format on ESA/390 hardware | DMKVAT (unchanged path) |
| D-14 | **`LRA` (via `DMKVAXLA`)** returns the guest real address, with exceptions turned into CP's "interrupt code" convention, not LRA's condition codes 1-3 | A guest relying on `LRA` cc 1-3 sees the wrong cc | DMKVAX |

Two behaviours are *more* correct than before: an ESA/390 guest gets no
location-80 timer (DMKDSP), and an empty reader answers `SSCH` by
interruption rather than with cc 1 (DMKVSP).

## 4. For M9 (64-bit)

- **CP still runs in AMODE 24.**
  - Every guest address CP forms needs `LR`/`AR`, not `LA`, and `TRANS` needs `OPT=AMODE31`.
  - M9 changes the rule (AMODE 64, `LA` → `LAY`/`LG`), and every site listed above is a site to revisit.
- **`LA Rx,n(,R0)` never adds R0.** Base or index register 0 means "none". Grep for `(,R0)` and `(R0,` in every deck before the conversion.
- **Shadow tables become region/segment/page tables** (ASCE types 00-11). DMKVAX's structure carries over: the walk, the per-ASCE set, the invalidation via `VMINVPAG`. Its entry formats don't.
- **Real prefixing and `SIGP`** are needed for SMP guests (D-1).
- **IDAWs** (D-3) are needed for 64-bit buffers too (format-2 IDAWs).
- **SCLP** (D-5) is required by any z/Architecture Linux.
- **The 912 self-relative branches** of R-26 remain.
